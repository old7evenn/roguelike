# Задачі для контриб'ютора

Цей файл для того, хто долучається до проєкту, а не для автора (у автора свій план у [ROADMAP.md](ROADMAP.md)).
Спершу прочитай [AGENTS.md](../AGENTS.md): там архітектура, куди класти нове і правила стилю. Якщо працюєш через ШІ-агента, дай йому прочитати AGENTS.md і цей файл (Claude Code, Codex, Cursor та інші підхоплюють AGENTS.md самі).

## Як працюємо

1. Автор додає тебе в колабораторів репозиторію `old7evenn/roguelike`. Прийми запрошення на GitHub.
2. Налаштуй git на своє ім'я й пошту з GitHub, щоб коміти рахувались за тобою:
   ```bash
   git config user.name "Твоє Ім'я"
   git config user.email "пошта@з-github"
   ```
3. `git clone git@github.com:old7evenn/roguelike.git && cd roguelike && npm ci && npm run dev`
4. Під кожну задачу окрема гілка від свіжого `main`: `git switch main && git pull && git switch -c feat/sound`.
5. Коміти у форматі Conventional Commits (`feat: add sound effects`, `test: ...`, `docs: ...`), англійською, по одній логічній зміні на коміт.
6. Перед пушем: `npm run lint && npm test && npx tsc`. Якщо міняв породи, предмети чи статі, ще `npm run balance`.
7. `git push -u origin feat/sound` і відкрий Pull Request у `main`. CI прожене лінт, тести й білд на PR.
8. **У `main` напряму не пушити**: пуш у `main` одразу деплоїть гру. Мерджить автор після рев'ю.

Автор захищає проєкт сам і має пояснити будь-який рядок, тому пиши просто і зрозуміло. Краще менший PR, який легко прочитати, ніж великий «все й одразу». Відміть задачу тут (`[x]`) у тому самому PR.

## Задачі

Від простої до складної. Беріть по порядку або за смаком, але одна задача — один PR.

### 1. [ ] Плейтест
Пройди гру (або спробуй) хоча б 2–3 рази: https://old7evenn.github.io/roguelike/
Запиши враження в `docs/PLAYTEST.md`: на якому поверсі помер, що було незрозуміло, що занадто легко чи важко, баги (з seed з URL, щоб відтворити).
Відміть у [ROADMAP.md](ROADMAP.md) і в README пункт «Гру пройшла хоча б одна людина, крім автора», якщо дійшов до кінця.

### 2. [x] Екран довідки
Клавіша `?` (або `H`) відкриває поверх гри оверлей зі списком клавіш і коротким поясненням, що є що на карті (герой, привиди-монстри, чашки й палички-предмети, сходи). Частина цього вже є в бічній панелі (`ui/sidebar.ts`), тож довідка може бути докладнішою. `Esc` закриває.
- Новий `Input` `help` у `ui/input.ts` (з прив'язкою за `KeyboardEvent.code`).
- `HelpScreen` у `ui/screens/`, відкривається через `ui.push`, як інвентар.
- Тексти українською.

### 3. [ ] Новий вид предмета: захист
Зараз є зілля (`potion`) і зброя (`weapon`). Додай `kind: 'armor'` з `defenseBonus`, наприклад «светр» (+1 захисту) і «ковдра» (+2, глибше).
- Дані в `ItemTypes` (`world/items.ts`), без підкласів. Логіку використання — в `UseItemAction`.
- Герой носить одну броню, як одну зброю: нова замінює стару.
- Тести в `tests/items.test.ts`. Після зміни — `npm run balance`, win rate не повинен сильно стрибнути.

### 4. [x] Звук через Web Audio API
Короткі синтезовані звуки (без аудіофайлів, через `OscillatorNode` + `GainNode`) на події гри: удар, смерть монстра, підбір предмета, спуск сходами, поразка, перемога.
- Окремий модуль у `ui/` (наприклад `ui/sound.ts`), який підписується на `game.events`. `world/` нічого не знає про звук.
- `AudioContext` створювати після першого натискання клавіші (браузери блокують автозвук).
- Клавіша `M` вмикає й вимикає звук; вибір зберігати в `localStorage` (у `try/catch`).
- Це закриває пункт «звук і музика (Web Audio)» у README і «Звук через Web Audio API» в ROADMAP.

### 5. [ ] Статистика забігу
На екранах поразки й перемоги показати: поверх, кількість ходів, скільки монстрів переможено (за породами), seed і посилання, щоб зіграти той самий забіг.
- Рахувати в `ui/` за подіями `death` / `depthChanged` або додати лічильник у `Game`, якщо так простіше; тоді з тестом.

### 6. [ ] Система енергії (швидкість акторів)
Швидкі монстри ходять частіше за героя, повільні рідше. Класичний підхід: кожен актор щоходу отримує енергію за своєю `speed`, і діє, коли набрав поріг.
- `speed` у `Breed` (наприклад «неспокій» швидкий, «тягар» повільний), у героя нормальна швидкість.
- Змінюється цикл у `Game.update()`, тому обов'язково тести в `tests/` і детермінізм для того самого seed.
- `npm run balance` до і після, результат напиши в описі PR.
- Найскладніша задача: краще спершу обговорити підхід з автором.
